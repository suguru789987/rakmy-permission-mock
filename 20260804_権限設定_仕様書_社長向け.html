2026-08-03 ／ ラクミー経営管理

第1部｜経営判断のための要約

1. 一言でいうと

「誰に何を見せるか」を、お客様自身が設定できるようにする機能。

2. いま何が起きているか

現在の権限は 3種類の固定 です。

現行の権限 実質の意味
master 全部見える・全部触れる
manager 本部として全社が見える
shop_manager 店長として自店舗が見える

この3つしかないため、お客様から次のような要望が来ても設定で応えられません。

  • 「経理担当には全社のお金は見せたいが、従業員の給与は見せたくない」
  • 「エリアマネージャーには担当の2店舗だけ見せたい。他店は見せたくない」
  • 「顧問税理士に見せたいが、数字を変更されては困る」
  • 「アルバイトリーダーには売上だけ見せたい。原価は見せたくない」

結果として現場は、見せたくない数字まで見せるか、必要な人にアクセスを与えないかの二択になっています。前者は情報管理上のリスク、後者は「使えないから使わない」に直結します。

3. 事業上の意味

受注条件になっている案件があります。 多店舗展開のお客様ほど「エリアマネージャーに担当店だけ」「親会社・税理士に閲覧だけ」という要件が強く、現行の3権限では要件を満たせません。

解約リスクの低減にもつながります。 「権限が分けられないから本部の一部しか使っていない」という状態は、利用率が上がらず、価値を実感されないまま更新時期を迎える典型パターンです。

4. 今回のリリース範囲と、その後

権限は誤って塞げば業務が止まり、誤って通せば情報が漏れる性質のため、段階的に入れます。

段階 内容 状態
今回 画面単位の閲覧制限。会社スコープ／店舗スコープの設定 ステージング検証中
次 操作（登録・編集・削除）の制限 未着手
その次 データ範囲の制限（担当外店舗の数字を出さない） 未着手
最後 指標単位の制御・監査ログ 未着手

既存のお客様への影響はありません。 リリース時に、現行の3権限と同じ動きをするプリセットを用意します。今まで見えていたものは今までどおり見え、設定を触らなければ何も変わりません。

第2部｜機能の全体像

5. 設計の骨格（3つの原則）

この機能は次の3つの考え方でできています。以降の操作フローはすべてこの原則から導かれています。

原則① 権限はロール（役割）経由で与える

権限を人に直接くっつけるのではなく、権限 → ロール → ユーザー の順で適用します。

なぜそうするか。 人ごとに権限を作り込むと、従業員が増えるほど設定が増殖し、誰がどこまで見えるのか把握できなくなります。「店長」という権限をひとつ作れば、店長が10人でも設定はひとつ。修正も一箇所で済みます。

原則② 「権限」と「担当店舗」は別々に決める

権限（どの画面を見せるか）は権限設定画面で決め、担当店舗（どの店のデータか）は割当画面で人ごとに決めます。

なぜそうするか。 同じ「エリア長」でも、Aさんは2店舗、Bさんは3店舗を担当します。ここを権限側に持たせると、担当店舗の組み合わせの数だけ権限を作ることになり、破綻します。権限は少数を共有し、店舗は人ごとに紐付ける設計にしています。

原則③ 1人に1つの権限（2026-08-03 決定・暫定）

1人が同時に持てる権限は1つです。別の権限を付け直すと、前の権限は自動的に外れます。

なぜそうするか。 「この人は結局何が見られるのか」が権限名だけで確定します。複数の権限を重ねて合算する方式だと、権限名を見ても実際に見える範囲が分からず、合算結果を計算しないと判断できません。権限の点検が難しくなります。

兼務の扱い。 「店長 兼 本部経理」のような兼務は、「店長＋経理」という権限を新しく作って割り当てます。役職（従業員台帳の肩書き）が兼務でも、権限は1つです。役職と権限は別物という整理です。

副作用も認識しています。 兼務の組み合わせが増えるほど権限が増えます。運用してみて権限が増えすぎるようなら見直す前提の暫定決定です。

6. 画面の構成（全9画面）

# 画面 何をする場所か
1 権限一覧 すべての権限を一覧で見比べる（起点）
2 権限編集／新規作成 権限そのものを作る・直す
3 指標一覧 その権限で見せる数字を選ぶ
4 指標条件設定 見せる数字をまとめて作り込む
5 マイテンプレート 作った数字のセットを保存して使い回す
6 役割サマリ 権限ごとに「誰が何人持っているか」を俯瞰する
7 ユーザー割当 人を選んで権限を付ける
8 割当編集（店舗紐付け） その人の担当店舗を決める
9 一括割当 ひとつの権限を複数人へ一度に配る

第3部｜主要フローと操作手順

以下は導入から運用までの実際の流れです。各フローに「何のためにやるか」と「この設計にした理由」を添えています。

画面遷移の全経路（24フロー・入口と戻り先の対応）は 20260803_09_権限設定_ケース別遷移フロー.tsv にまとめています。

フロー1｜導入時に権限を一括で用意する

目的： 導入初日に「権限が空っぽで誰も何も見えない」状態を避ける。お客様がゼロから27画面分を設定するのは現実的でないため、動く状態から始めてもらう。

誰が： 導入担当（CS）またはお客様のオーナー

操作手順

  1. 権限設定を開く → 初回は権限テンプレートの画面が出る
  2. 用意する権限を選ぶ（既定は全部オン）
    - オーナー（全権）… 全権固定
    - 会社ロール（権限母体）… 本部・全社の土台。ここから経理／人事を派生させる
    - 店長（権限母体）… 店舗運営の土台。エリア長などはここから派生させる
    - 従業員 … 閲覧中心
  3. それぞれの初期値を選ぶ（推奨プリセット／操作可／閲覧のみ／なし）
  4. 「適用」→ 権限一覧に5権限が登録された状態で着地
  5. 一覧の上部に「登録しました。内容を確認し、必要なら権限編集で調整してください」と表示される

この設計にした理由

「母体を作って後で分ける」流れを想定しています。導入時は会社ロールをひとつの母体として作り、運用が回り始めてから「経理」「人事」に分割します。最初から細かく分けると、まだ運用が固まっていない段階で誤った線引きを固定してしまいます。

フロー2｜現行に無い権限を新しく作る（本機能の主目的）

目的： 「経理だけ」「エリアマネージャー」など、現行の3権限では表現できなかった中間の権限を作る。この機能の価値の中心。

誰が： お客様の管理者（本部）

操作手順

  1. 権限一覧 → 「＋ 権限を新規作成」
  2. ① ベースを選ぶ … 近い権限を土台にする
    - ベーステンプレート（オーナー相当／本部管理／店長／従業員）
    - 既存権限をコピー（運用中の権限を複製して差分だけ直す）
    - プレーン（すべて「なし」からゼロで作る）
  3. ② 基本設定 … 権限名と区分（会社／店舗）を決める
  4. ③ 権限内容 … 画面ごとに 操作／閲覧／なし を調整する
    - 画面名をクリックすると、その場で内訳（機能）→ 数字（指標）まで掘り下げて設定できる
    - 上部に「何画面を許可したか」の許可数が出る
  5. 最下部で 保存、または 「ユーザー割当で紐付け →」（フロー4へ直行）

この設計にした理由

ステップの順番が「識別 → 中身 → 確定」になっています。 先に区分（会社／店舗）を決めるのは、区分によって次に出る画面リストが変わるためです。会社の権限を作るのに店舗専用の画面を並べても意味がなく、逆も同じです。順番を逆にすると、設定した後に区分を変えて設定がやり直しになります。

ゼロから作らせない設計にしています。 27画面53機能をゼロから設定するのは現実的でないため、必ず「近いものを選んで差分を直す」形にしています。実際の顧客運用もこの形になります。

フロー3｜既に使っている権限を修正する

目的： 「この権限、この画面も見せたい」という日常的な微修正を、最短で終わらせる。

誰が： お客様の管理者

操作手順

  1. 権限一覧で、変えたい権限の行 × 変えたい画面の列 のマス目をクリック
  2. 権限編集が開き、そのマス目に該当する箇所へ自動でスクロールして一時的に光る
  3. なし → 閲覧 などに変更して保存
  4. 元いた画面に戻る（一覧から来たら一覧へ、割当から来たら割当へ）

この設計にした理由

「見つけた場所から直せる」ことを重視しています。 一覧で問題に気づいたのに、編集画面を開いてから該当箇所を探し直すのでは、27画面の中から目的の項目を見つける手間がかかります。マス目クリックで直接その場所へ飛ぶことで、気づきから修正までを一続きにしています。

戻り先が元の画面になるのも同じ理由です。 どこから来ても一覧に戻される作りだと、続けて別の修正をするたびに元の場所へ辿り直すことになります。

フロー4｜作った権限を人に配る

目的： 権限を実際に効かせる。ここまでは定義を作っただけで、誰にも適用されていない。

誰が： お客様の管理者

入口が3つあり、やりたいことによって使い分けます。

4-A ひとつの権限を複数人へ一度に配る（一括割当）

新しく権限を作った直後や、大量に配るときに使います。

  1. 権限編集の最下部 → 「ユーザー割当で紐付け →」
  2. 管理者一覧が出て、各人に 〔含める〕チェック と 〔対象店舗〕 が並ぶ
  3. 複数人にチェックを入れ、それぞれの担当店舗を選ぶ
  4. 一括保存 → 役割サマリに着地し、「割当ユーザー ○名」が更新されたことを確認できる

割当ミスを防ぐ仕掛けが3つ入っています。

仕掛け 防ぐ事故
区分フィルタ … 店舗ロールを配るときは店舗所属者のみ、会社ロールを配るときは本部所属者のみ表示 本部の経理に店舗の権限を付けてしまう
「現在のロール」列 … 各人が今どの権限を持っているかをその場に表示 すでに店長なのに従業員権限を重ねてしまう
置き換えの明示 … 既に別の権限を持つ人の行に「既に『店長』を保持。含めると置き換わります」、この権限で登録済みの人に「✓ この権限で登録済み」を表示。保存時にも確認が入る 1人1ロールのため、含めると前の権限が外れる。意図しない権限の剥奪を防ぐ

この設計にした理由

役職（肩書き）を判断材料にしていません。 従業員台帳の役職名は「店長」「マネージャー」「店長 兼 本部経理」など命名がお客様ごとにバラバラで、信頼できません。実際に今持っている権限を表示して判断してもらう作りにしています。

「含める」チェックを店舗選択と統合していません。 店舗を選んだ瞬間に権限が付く作りだと、誤クリックがそのまま権限付与になります。明示的なチェックを安全装置として残しています。

4-B 人を選んで権限を付け直す（ユーザー割当）

入社・異動・退職など、人単位の変更のときに使います。

  1. ユーザー割当（管理者一覧）を開く
  2. 対象の人を選ぶ
  3. 持たせる権限を1つ選ぶ（ラジオ。先頭に「割当なし」）。別の権限を選ぶと現在の権限から置き換わる旨が行に表示される
  4. 店舗ロールを付けた場合は担当店舗を紐付ける

4-C 権限から逆引きして配る（役割サマリ経由）

「この権限、誰が持っているんだったか」から入るときに使います。

  1. 役割サマリで各権限の「割当ユーザー ○名」を確認
  2. 「割当へ →」 をクリック
  3. その権限を持つ人だけに絞り込まれた状態でユーザー割当が開く

この設計にした理由

同じ目的地に3つの入口を用意しています。 「権限を作ったから配る」「人が入ったから設定する」「この権限を持つ人を確認したい」は、それぞれ思考の出発点が違います。どれかひとつに強制すると、他の2つのケースで遠回りになります。ただし付与の実体は割当画面ひとつに集約しており、二重管理は起きません。

フロー5｜担当店舗を紐付ける

目的： 「どの店のデータを扱えるか」を人ごとに決める。権限とは別軸の設定。

誰が： お客様の管理者

操作手順

  1. ユーザー割当で店舗ロール（店長・エリア長など）を付ける
  2. 店舗ピッカーが出る
    - 店長 … 自店舗を1つ選ぶ（複数店舗の兼任も可）
    - エリア長 … 複数店舗を選ぶ。先頭の「全店」チェックで一括選択も可
  3. 保存すると、一覧の「有効範囲」列に実際の店舗名が出る（例：「店舗（渋谷店）」「指定店舗群（3店舗：…）」「全店（5店舗）」）

この設計にした理由

担当店舗を権限編集側に置いていません。 権限編集の画面には、掌握店舗数も店舗名も一切表示しません。両方に店舗設定があると「どちらが本当か」が分からなくなり、片方だけ直して事故が起きます。担当店舗の唯一の正解は割当画面、と決め切っています。

ただしガバナンス上の警告だけは権限編集にも出します。「店舗ロールなのに店舗が未設定の人が○名います」という警告です。設定はできないが、問題があることは気づける、という線引きです。

フロー6｜見せる数字（指標）を選ぶ

目的： 同じ画面を見せても、そこに出る数字は権限ごとに変えたい。「売上分析は見せるが、原価率は見せない」といった調整。

誰が： お客様の管理者

操作手順

  1. 権限一覧の行 → 「指標一覧（○）」（○＝その権限で見える指標数）
  2. 指標が 🏬店舗指標／🏢会社指標 のタブで並ぶ。各指標をクリックで 表示⇄非表示
  3. 数が多いときは 「指標条件設定 ＞」 へ
    - ① 土台を選ぶ … 推奨テンプレート（現場スタッフ向け／店長向け／管理者・経理向け）、他の権限からコピー、まっさら、保存済みテンプレートを読込
    - ② 調整する … 系統ごとに一括表示／非表示、個別クリックで例外指定、条件ルール（対象 × 種別 × 公開範囲 × 表示可否）でまとめて設定
  4. 「適用して指標一覧へ」 で反映
  5. よく使う組み合わせは マイテンプレートに保存して他の権限にも使い回せる

初期値は自動で決まります。 手作業をゼロから始めなくて済むよう、指標の性質に応じた既定値が入っています。

指標の性質 従業員 店長・エリア長 経理・人事
現場で使う数字 表示 表示 表示
店長まで（原価率・人件費など） 非表示 表示 表示
経営機密（全社の利益・店舗別ランキングなど） 非表示 非表示 表示

初期状態の実数：従業員＝店舗17／会社0、店長・エリア長＝店舗36／会社8、経理・人事＝店舗36／会社25。

この設計にした理由

機密ランクを画面に出していません。 「この指標は経営機密です」というラベルを表示すると、お客様が指標を選ぶたびにランクの妥当性を判断させることになります。ランクは初期値を決めるためだけに内部で使い、画面上はシンプルな表示／非表示のスイッチにしています。

会社の数字を店舗の人に見せることを禁止していません。 「うちは店長にも全社の利益を見せる方針」というお客様もいます。既定はオフにしつつ、管理者が意図的にオンにできる設計です。ただし数字を見せることと、他店の明細を見られることは別で、後者は構造的に遮断されます。

フロー7｜全体を点検する

目的： 設定が増えた後に「誰が何をどこまで見られるのか」を俯瞰し、抜けや持たせすぎを見つける。

誰が： お客様の管理者、CS

操作手順

  1. 権限一覧 … 権限 × 画面のマトリクスで見比べる
    - 一覧画面権限（青）／設定画面権限（緑） の2タブ
    - 上部の「表示ロール」で見比べたい権限だけに絞る
    - 「権限列設定」で見たい画面だけを列に出す（選択は次回も記憶される）
    - ヘッダーの会社名をクリックすると会社スコープ／店舗スコープが切り替わり、一覧の権限と画面が連動して入れ替わる
  2. 役割サマリ … 権限ごとに「許可数」「割当ユーザー数」「店舗未設定の警告」を一覧
  3. 問題を見つけたらその場から権限編集または割当へ遷移

この設計にした理由

既定を「折りたたみ」にしています。 27画面を全部列に出すと横に長大な表になり、かえって読めません。既定では要約された数列だけを表示し、必要なときに展開する形にしています。

列の選択を記憶します。 点検作業は繰り返し行うもので、毎回同じ列を選び直すのは無駄だからです。

フロー8｜オーナー専用の操作

目的： 全権の管理と委譲。権限設定そのものを守る。

誰が： オーナー（全権保持者）のみ

操作手順

  1. 権限一覧の右上 「👑 オーナー操作」
  2. 指標管理 … 全指標を一覧で確認（読み取り専用）
  3. 付与先を指定 … 全権を委ねる相手を指名

この設計にした理由

オーナーは権限一覧の表に出しません。 全権固定で編集できないため、設定対象の中に混ぜると「なぜ編集できないのか」という混乱を生みます。専用のメニューに分けています。

第4部｜判断が必要な点

現在の実装は画面単位の閲覧制限までです。検証で以下が確認された場合、次の段階の開発をどこまで前倒しするかの判断が必要になります。

① データ範囲の制限（優先度：高い見込み）

画面を制限しても、担当外店舗の数字が混ざる可能性があります。この場合、フロー5で店舗を紐付けても実際には効かず、お客様が最も欲しがる「エリアマネージャー」が作れません。

② 操作の制限（優先度：高い見込み）

閲覧だけを許可しても、その画面で保存ボタンが機能してしまう可能性があります。この場合「見るだけの権限」が作れず、税理士・親会社向けの要望に応えられません。

③ 数字単位の制限

フロー6の指標制御が効かない場合、「売上は見せるが原価は見せない」がひとつの画面の中で分けられません。

いずれも検証（20260803_03a / 03b）で実測し、作れない権限が何かを一覧化したうえで開発順序をご相談します。
